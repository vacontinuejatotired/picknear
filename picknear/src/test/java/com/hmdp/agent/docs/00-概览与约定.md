# AI 模块测试 — AI 代码生成约束清单

> 本文档是给 **AI（如 Claude、Copilot）看的指令集**，目的是让 AI 自动生成**能一键运行**的自测代码。
> 所有约束均为**硬性要求**，AI 不得违反。

---

## ⛔ 绝对禁止清单（Anti-Patterns）

AI 生成测试代码时，**严禁**出现以下写法：

| # | 禁止行为 | 错误示例 | 正确做法 |
|---|---------|---------|---------|
| 1 | 使用 PowerMock | `@RunWith(PowerMockRunner.class)` | 项目未引入 PowerMock，只能用 Mockito |
| 2 | Mock 静态方法 | `MockedStatic<Xxx>`、`mockStatic(Xxx.class)` | 项目依赖的库非静态，不需要 mockStatic |
| 3 | `new` 注解注入的依赖 | `AiServiceImpl service = new AiServiceImpl()` | 用 `@InjectMocks`，容器自动注入 Mock |
| 4 | 单元测试连真实数据库 | `@SpringBootTest` + 真实 MySQL | Mock 所有 Service/Repository 层；集成测时用 H2/Testcontainers |
| 5 | 直接断言 SseEmitter 对象 | `assertThat(emitter).isNotNull()` | 用 `ArgumentCaptor<Object>` 捕获 `emitter.send()` 的事件内容再断言 |
| 6 | 没等异步就断言 | 直接 `assertThat(result)` | 必须用 `CountDownLatch` 或 `Awaitility` 等待完成 |
| 7 | 使用 `Thread.sleep(t)` 等待异步 | `Thread.sleep(3000)` | 用 `CountDownLatch.await(5, SECONDS)` |
| 8 | 断言用 JUnit 的 `assertEquals` | `assertEquals(a, b)` | 必须用 AssertJ：`assertThat(a).isEqualTo(b)` |

## 🧪 测试基类约定

所有测试类 **必须** 遵循以下注解组合：

### 单元测试（纯 Mock，无 Spring 容器）

```java
@ExtendWith(MockitoExtension.class)
class XxxServiceTest {
    // 所有非关键 Mock 用 lenient().when()，不依赖全局 Strictness
}
```

### 集成测试（Spring 容器 + Mock 外部）

```java
@SpringBootTest
@Transactional              // 自动回滚
@Rollback
@TestPropertySource(locations = "classpath:application-test.yml")
class XxxIntegrationTest {
    // ...
}
```

## ✅ 断言规范

所有断言**必须**使用 AssertJ，**必须**加 `.as("描述")`：

```java
// ✅ 正确
assertThat(result)
    .as("AI 回复不应为 null")
    .isNotNull();

assertThat(capturedValue)
    .as("SSE 事件应包含错误码 5001")
    .contains("5001");

// ❌ 禁止
assertEquals(expected, actual);
assertNotNull(result);
```

## 🎭 Mock 兜底返回值规则

AI 在 Mock 时**必须**为所有返回值提供安全兜底，禁止返回 null（除非被测试逻辑预期 null）：

| 类型 | 正确 Mock 写法 |
|------|---------------|
| `List<T>` | `List.of()` / `Collections.emptyList()` |
| `Map<K,V>` | `Map.of()` / `Collections.emptyMap()` |
| `Optional<T>` | `Optional.of(value)` 或 `Optional.empty()`（不可直接返回 null） |
| `String` | `""` |
| `Boolean` | `false` |
| `Long/Integer` | `0L` / `0` |

```java
// ✅ 正确
when(blogService.count()).thenReturn(100L);
when(chatMemory.get(any())).thenReturn(List.of());

// ❌ 禁止——可能 NPE
when(blogService.count()).thenReturn(null);
```

## 🔄 异步/流式测试模板

### SseEmitter 测试（推荐：反射同步 + mock verify）

**原理**：通过 `ReflectionTestUtils` 把线程池替换为内联执行器，异步变同步。无需 `CountDownLatch`，直接 `verify()`。

```java
@Test
void should_push_reply_when_chat_with_toolcall() {
    // 1. 异步同步化（@BeforeEach 中执行一次即可）
    ReflectionTestUtils.setField(aiService, "aiTaskExecutor",
            (Executor) Runnable::run);

    // 2. Mock SseEmitter（不是 new！不是 spy！）
    SseEmitter emitter = mock(SseEmitter.class);

    // 3. 执行（同步化后直接阻塞调）
    aiService.chatWithToolcall("你好", TEST_CONVERSATION_ID, emitter);

    // 4. 直接 verify（无需 latch）
    verify(emitter).send(any(SseEmitter.SseEventBuilder.class));
    verify(emitter).complete();
}
```

| 变量/操作 | 用途 |
|-----------|------|
| `ReflectionTestUtils.setField(aiService, "aiTaskExecutor", (Executor) Runnable::run)` | 将线程池替换为当前线程直接执行，异步变同步 |
| `mock(SseEmitter.class)` | 不启动真实 SSE 连接，可 verify 调用次数 |
| `any(SseEmitter.SseEventBuilder.class)` | 避免 `any()` 歧义（SseEmitter.send 有两个重载） |
| `verify(emitter).send(...)` | 同步化后 call 返回时所有异步 lambda 已执行完 |

> **为什么不用 CountDownLatch？** `@Resource(name="aiTaskExecutor")` 线程池替换后，`CompletableFuture.runAsync(task, aiTaskExecutor)` 退化为 `task.run()`，主线程与异步 lambda 同线程、同 `ThreadLocal`。直接用 `verify()` 即可。

### Fallback：CountDownLatch + spy（无法反射替换时）

仅当被测方法内部直接 `new Thread(() -> {...}).start()` 或无法反射替换 Executor 时使用：

```java
@Test
void should_push_reply_when_chat_with_toolcall() throws Exception {
    SseEmitter emitter = new SseEmitter(SSE_TIMEOUT_MS);
    SseEmitter spy = spy(emitter);
    CountDownLatch latch = new CountDownLatch(1);
    ArgumentCaptor<Object> eventCaptor = ArgumentCaptor.forClass(Object.class);
    doAnswer(invocation -> {
        eventCaptor.capture();
        latch.countDown();
        return null;
    }).when(spy).send(eventCaptor.capture());

    aiService.chatWithToolcall("你好", TEST_CONVERSATION_ID, spy);

    assertThat(latch.await(5, TimeUnit.SECONDS))
            .as("异步调用应在 5s 内完成").isTrue();
    assertThat(eventCaptor.getValue()).as("应推送回复内容").isNotNull();
}
```

## 🧹 前置条件清理（@BeforeEach 模板）

```java
@BeforeEach
void setUp() {
    // 1. 重置 Mock 计数器
    Mockito.reset(chatClient, chatMemory, toolBeanCollector);

    // 2. 清理 Redis（若使用 embedded Redis）
    // redisTemplate.execute((RedisCallback<Object>) conn -> {
    //     conn.flushDb();
    //     return null;
    // });

    // 3. 设置默认 Mock 行为（兜底）
    lenient().when(chatClient.prompt()).thenReturn(chatClientRequestSpec);
    lenient().when(chatClientRequestSpec.user(any())).thenReturn(chatClientRequestSpec);
    lenient().when(chatClientRequestSpec.call()).thenReturn(chatClientResponseSpec);
    lenient().when(chatClientResponseSpec.content()).thenReturn(TEST_LLM_REPLY);
}
```

## 📦 两阶段生成策略

| 阶段 | 范围 | 触发条件 |
|------|------|---------|
| **阶段一 · 链路打通** | 链路A(JSON同步)、链路B(SSE+PASS)、链路C(SSE+PLANNING→SubTaskAgent) | **每次 agent 模块变更后必测** |
| **阶段二 · 单元覆盖** | Hook、Guard、TaskPlanner、SubTaskAgent 等单人模块 | 仅当对应类/接口变更时按需补全 |

AI 生成代码时默认只走阶段一，除非被明确要求"补充 Xxx 类的单元测试"。

## 🧩 依赖坐标（防止 AI 臆造包名）

```xml
<!-- pom.xml 中已有的测试依赖，生成代码时不要加新依赖 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>
```

| 依赖 | 来源 | 项目中是否已有 |
|------|------|---------------|
| JUnit 5 (jupiter) | spring-boot-starter-test 传递 | ✅ |
| Mockito 5 | 同上 | ✅ |
| AssertJ 3 | 同上 | ✅ |
| Spring Test (ReflectionTestUtils) | 同上 | ✅ |
| Awaitility / Testcontainers / H2 | 需另加 | ❌ **禁止臆造** |

## 速查：AssertJ 断言大全

```java
// 字符串
assertThat(s).isEqualTo("期望值").contains("子串").startsWith("前缀").isEmpty();

// 集合
assertThat(list).hasSize(3).contains("a").doesNotContain("b");

// Map
assertThat(map).containsKey("key").containsValue("val");

// 布尔
assertThat(b).isTrue().isFalse();

// 异常
assertThatThrownBy(() -> method()).isInstanceOf(IllegalArgumentException.class)
    .hasMessageContaining("错误信息");

// Optional
assertThat(optional).isPresent().get().isEqualTo("value");
assertThat(optional).isEmpty();

// 链式
assertThat(result)
    .as("校验点描述")
    .extracting(Result::getContent)
    .isEqualTo("期望");
```
