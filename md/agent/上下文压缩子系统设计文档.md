## 0. 实施快照（2026-09-03 拍板，先行落地项，正文据此解读）

> - **JSON 同步对话模式已废弃**：对话仅 SSE（`/agent/string/send` 固定流式，Accept 协商删除；`chatReturnStringResult` 已随 `AiService` 删除）。
> - **SensitiveWordHook 默认关闭**（`agent.hook.sensitive-word.enabled=false`），多轮脱敏语义留 TODO。
> - **日期/时间注入不做**：关注点在"上下文传递/记忆"，非"模型知道今天几号"。
> - P1 记忆回放作用域收敛为 **SSE 链路**（下文凡"双模/JSON 模式"表述均按已废弃处理）。
> - **压缩 P2 对话级异步压缩已落地（2026-09-03，feature 分支）**：recordTurn 写后投递 event → 独立 compressExecutor（AbortPolicy + CleanupDecorator）→ Redisson 锁守卫 → TailBatchSelector（keep 尾窗/token 预算）→ LlmConversationSummarizer（compressChatClient qwen-flash，JSON 摘要+keyData）→ FidelityAssurance 保真回填 → Mem 单 key 原子提交（summary+uptoId）；回放升级为 [摘要]+id>uptoId 增量（不重不漏，原值永在 agent_message）。ChatModelConfig 同处接管主模型（@Primary 还原 auto-config）+ 压缩模型。压缩旁路 fail-open：任何异常不阻断请求主链，dirty 自愈 + @Scheduled sweeper。
> - **P3（工具结果级保真压缩 + 原值 Redis 存档）后置**，蓝图为本文 §6.3。

## 1. 背景与目标

Agent 有两类上下文膨胀，现实现均**不保真、不可追溯、压缩同步进行**：

1. **跨请求多轮历史**：`agent_message` 已落库完整多轮历史，但**从不回灌模型**——每次请求 = `system + 当条 user`（JSON 模式 `AiServiceImpl`；SSE 直调 `StreamingChatInvoker.chatModel.stream`）。模型侧无可累积上下文。
2. **单请求工具结果累积**：planner→子 Agent 工具循环中工具原始返回**截完即弃**：`ToolCallExecutor.limitToolResult` 硬截 1200 → 策略层 `ResultCompressor`/`TruncateCompressor`/`LlmCompressor`(stub) 压缩至 80 → planner/historySummary 截 50。数值/语义三处不可逆收缩，全部在主链路同步执行。

目标（与用户对齐）：
- **保真**：工具结果不丢失、原值可查、压缩后数值/语义不变。
- **异步**：压缩由**独立小模型 + 后台检测 + 独立异步队列**处理，非请求路径同步 compact。
- **可扩展**：核心组件一律端口化（接口 + 可替换实现），新增阈值策略/摘要器/存档介质不改调用方。
- **分层交付**：P1 记忆回放地基 → P2 对话级异步压缩 → P3 工具结果级压缩升级。

## 3. 总体架构

```
                         ┌──────────────────── 请求主链（同步，模型侧视角）────────────────────┐
 JSON /agent/string/send │  AgentContext.history ← ConversationReplayService.replay(cid,userId) │
 SSE                     │      = [System(主提示)] + [System(历史摘要,可选)] + [近期完整 messages] + [User(本轮)]   │
                         └────────────────────────────────────────┬─────────────────────────────┘
                                                                  │ recordTurn(afterCommit) 发事件
   ┌────────────── 后台异步压缩链（compressExecutor，与请求链隔离） ───────────────┐
   │ ConversationCompressionDispatcher(收事件) → CompressTaskLockGuard(Redisson 锁) │
   │ → TailBatchSelector(切最旧未压批) → LlmConversationSummarizer(小模型 JSON 摘要)  │
   │ → FidelityAssurance(数值断言回填) → RedisConversationMemoryStore.commit(uptoId) │
   └───────────────────────────────▲───────────────────────────────────────────────┘
                                    │ @Scheduled sweeper：dirty 自愈 / TTL / status!=0 清理
  工具调用旁路：ToolCallExecutor.delegate.call() 原始值 → RedisToolRawArchiver 存档(agent:toolraw:*)
```

三层职责严格分离：
- **memory 层**：只管"读什么给模型"（回放视图组装）与"摘要视图怎么存"（checkpoint 原子读写）——不含任何压缩逻辑。
- **compression 层**：只管"何时压、压哪些、怎么压、压完如何提交"——不关心消息如何被模型消费。
- **execution 层（P3）**：只管"工具原值落盘 + 保真摘要"，是既有工具策略的替换实现。

## 4. 新增包结构（全部单职责小类，方法可外置一律外置）

全部落在 `com.hmdp.agent` 下，按现有顶层子包风格组织：

```
config/
  CompressionProperties          # 薄壳：仅 enabled；其余指向下方独立小类（避免一个上帝配置类）
  ContextCompressionProperties  # 阈值/窗口：replay-window-msg, keep-recent-turns, batch-turns,
                                #   trigger.{token-threshold,message-count}, summary.{max-tokens,keep-keydata}
  CompressionExecutorProperties # 池参数 core/max/queue + sweeper-interval
  CompressModelProperties       # 压缩小模型：provider=inherit|custom, model, base-url, api-key,
                                #   temperature, max-tokens, timeout（isCustomConfigured() 判断）
  ToolRawArchiveProperties      # 工具原值存档：enabled, ttl, prefix, debug-enabled
  ChatModelConfig               # 只做 @Bean 装配（主模型@Primary + compressChatModel + compressChatClient）
  ChatModelAssembler            # 装配逻辑外置（构造/观测标记注入），config 只留声明 → 可测

model/
  ReplayView        # record(summary, uptoId, messages, clipped)
  Mem               # record(summary, uptoId, version, updatedAt)  ← 摘要+游标同 key 原子写的最小单元
  PressureDecision  # record(compress, reason, droppedOldest)     ← 判定结果值对象，禁布尔透传

memory/                                     # —— P1/P2 对话记忆：只读组装 + 存储（无压缩逻辑）
  ConversationReplayService       # 门面：replay(cid,userId)→ReplayView；读 store + DB 尾部窗口
  Phase1PromptAssembler           # 组件：把 systemText+ReplayView+当前user 拼成 List<Message>（顺序确定性）
  ConversationMemoryStore         # 端口（接口）：read/update/delete(cid,userId,Mem)
  RedisConversationMemoryStore    # 适配器：单 key JSON 原子 SETEX/GET/DEL + 滑动续期
  ConversationMemoryKeyFactory    # 单一职责：key 生成（agent:conv:{cid}:mem / active / dirty）
  LoadProber                      # 组件：取 [checkpoint, tail] 待压载荷 → 消息对数 + 估算 token（喂压力判定）

memory/pressure/                           # —— P2 判定：端口 + 可替换实现
  TokenEstimator                  # 策略接口：estimate(CharSequence)→int
  HeuristicTokenEstimator         # 实现：CJK≈1token/字 + ASCII≈1/4 + 消息头开销，参数可校准
  ContextPressurePolicy           # 策略接口：shouldCompress(LoadProbe)→PressureDecision
  HybridPressurePolicy            # 实现：token 阈值 或 消息数下限（枚举 reason，不做 if-true/false 透传）

memory/compression/                        # —— P2 调度：事件 + 编排 + 锁 + 选择 + 摘要器，各司其职
  ConversationTurnRecordedEvent   # 事件值对象(cid,userId)
  ConversationCompressionDispatcher # 门面：@EventListener 收事件 → 校验 enabled/会话状态 → 组 CompressionTask → compressExecutor.execute
  CompressionTask                 # Runnable：显式持有(cid,userId,props 快照)；不碰 ThreadLocal
  CompressTaskLockGuard           # 装饰器：Redisson RLock tryLock(0,60s)；拿不到→置 dirty（幂等丢弃，交 sweeper）
  BatchSelector                   # 策略接口：select(mem, tail, props)→批次(消息起点/终点, 估算token)
  TailBatchSelector               # 实现：从 checkpoint 后的最旧批次开始，按 batch-turns/估算上限切
  ConversationSummarizer          # 策略接口：summarize(currentSummary, batch)→SummaryResult
  LlmConversationSummarizer       # 实现：compressChatClient + JSON {summary, keyData[]}（prompt 由 Composer 提供）
  SummarizePromptComposer         # 组件：压缩 prompt/JSON schema 外置，压缩器不沾模板字符串
  CompressionOrchestrator         # 瘦编排：锁→压力判定→select→summarize→commit→tail 前进则最多追平 2 次
  ConversationMemoryCleaner       # 清扫：@Scheduled dirty 自愈 + TTL 过期 + agent_conversation.status!=0 清理；purge(cid) 供未来归档端点
  CleanupTaskDecorator            # TaskDecorator：压缩池专用——跑前 set(null)/finally clear()，杜绝线程复用串扰（不挂 AgentContextPropagator）

memory/fidelity/                           # —— 保真（对话级），方法外置
  KeyDataExtractor                # 策略接口：extract(text)→List<String>
  NumericKeyDataExtractor         # 实现：正则抽数字/金额/百分比/日期（\d+(\.\d+)?(%|元|万|亿|年|月|日)?、\d{4}-\d{2}-\d{2}）
  FidelityAssurance               # 组件：断言 keyData 词元出现于 summary，缺漏按容量回填【数据点保留】或记观测属性，不静默丢数

execution/store/                           # —— P3 工具原值存档
  ToolRawArchiver                 # 端口：archive(cid,userId,toolName,args,raw)→key
  RedisToolRawArchiver            # 适配器：StringRedisTemplate + ObjectMapper（全仓惯例）存 JSON，TTL
  ToolRawKeyFactory               # 单一职责：agent:toolraw:{cid}:{toolName}:{ts}-{rand}

execution/compress/                        # —— P3 保真工具摘要
  FaithfulCompressor              # 组件：走 compressChatClient，JSON 摘要 + KeyData 断言回填；失败降级 TruncateCompressor
  ToolCompressPromptComposer      # 组件：工具压缩 prompt/JSON schema 外置

execution/strategy/（改动）                # TruncateCompressor 保留为兜底；LlmCompressor 由 stub 改为包装 FaithfulCompressor

observability/（复用）
  CompressionObservation          # 门面：把 mark(CallerType.SUBAGENT_COMPRESS, task)…finally clear() 收敛，压缩点共用
```

## 5. 设计模式 → 落点映射（一模式对应多个真实组件）

| 模式 | 落地 |
|---|---|
| 策略 Strategy | `TokenEstimator`、`ContextPressurePolicy`、`BatchSelector`、`ConversationSummarizer`、`KeyDataExtractor`（+既有 `ToolResultCompressor` 家族）——接口注入、实现可替换，靠配置激活不同实现 |
| 端口-适配器 Port-Adapter | `ConversationMemoryStore`(Redis 适配)、`ToolRawArchiver`(Redis 适配) |
| 门面 Facade | `ConversationReplayService`、`ConversationCompressionDispatcher`、`CompressionOrchestrator`（编排只做调度不做业务） |
| 装饰 Decorator | `CompressTaskLockGuard`(锁互斥包装任务)、`CleanupTaskDecorator`(池线程上下文清理)、既有 `GuardedToolCallback` |
| 观察者/事件 Observer | `ConversationTurnRecordedEvent` + `@EventListener`（写后投递，解耦 recordTurn 与压缩调度） |
| 建造/工厂 Builder-Factory | `ChatModelAssembler`(装配逻辑)、`ConversationMemoryKeyFactory`/`ToolRawKeyFactory`(key 收敛) |
| 模板方法 Template | `Phase1PromptAssembler`（消息顺序固定：System→摘要→历史→User，双模同源）；既有 `AbstractToolLoop` 沿用 |
| 值对象 Value Object | `ReplayView`、`Mem`、`PressureDecision`、`CompressionTask`、`ConversationTurnRecordedEvent`——跨层传值不传裸参/布尔 |
| 瘦编排 Thin Orchestration | `CompressionOrchestrator`/`ConversationCompressionDispatcher` 无业务 if 堆叠，条件全部由压力策略/锁守卫封装 |

**解耦铁律**：memory 层不 import compression 层；compression 层不 import execution 层；所有跨层依赖指向**接口**；事件只作"投递信号"，真正的队列是独立执行器的 BlockingQueue。

## 6. 模块详设

### 6.1 P1 记忆回放地基（Stage A 底座）

改：`AiServiceImpl`（JSON 走 `Phase1PromptAssembler` 拼 messages；SSE 异步段先算列表）、`StreamingChatInvoker.streamWithRetry` 增加 `List<Message>` 重载（保留旧三参给测试）、`ChatController` 两分支 `AgentContext.history` 改喂 `ConversationReplayService.recentMessages`、`AgentHistoryServiceImpl.recordTurn` 事务 afterCommit 发 `ConversationTurnRecordedEvent`（本段事件仅记录，压缩 disabled 时零开销）。
本段语义：摘要为空、只回放近期完整，窗口硬上限（`replay-window-msg`），模型第一次拥有多轮上下文。

> **P1 已实现（2026-09-03，由 `多轮记忆回放实现任务.md` 承接）**：历史读取点落在 `AiServiceImpl` 异步段（调 `ConversationReplayService.recentMessages`），**未改动** `ChatController`/`AgentContext.history`（死字段）；`StreamingChatInvoker.streamWithRetry` 增 `List<Message>` 四参重载（旧三参保留）；`ReplayMessageMapper` 策略负责 role→AI 消息映射，`Phase1PromptAssembler` 负责 [System]+历史+当前 User 拼装；`ReplayBudgetTrim` 按 `agent.replay.max-replay-chars`（默认 3000，近似 token）从最旧裁剪、最新一条恒保留——P2 读路径预算止损的 P1 兜底，P2 上线后自然退化为纯兜底。`recordTurn` 事务 afterCommit 事件属 §6.2 P2 写路径，**本段未做**。配置 `agent.replay.{enabled=true, keep-recent-turns=6, max-replay-chars=3000}`。

### 6.2 P2 对话级异步压缩（Stage A 本体）

触发：**写后投递为主**（`recordTurn` 唯一写入点，afterCommit 发事件）+ **读路径止损兜底**（replay 时若尾部窗口超预算且 worker 落后，裁最旧未压行出模型视野并置 dirty，DB 永不删、当前轮永不裁）+ **`@Scheduled` sweeper 自愈**（dirty/TTL/归档）。
阈值：`HybridPressurePolicy` 判 `LoadProbe`——token 估算(默认 3000) 或 消息对数(20) 或 摘要自身超限(二次收敛)；`HeuristicTokenEstimator` 只用于触发与预算（DashScope token API 不进热路径）。
队列：`compressExecutor` core1/max2/queue512/AbortPolicy（不用 CallerRuns——防压缩占用 SSE/Tomcat 收尾线程）；拒绝时 catch 置 dirty 交 sweeper。
一致性：`Mem(summary,uptoId,version,updatedAt)` **同一 key 单 SET 原子替换** → 读永远"旧版或新版"成对快照，杜绝"游标前进但摘要未写"的撕裂；单会话写者由 `CompressTaskLockGuard` Redisson RLock 互斥；增量天然幂等（只处理 `(uptoId, tail]`，commit 只推 `uptoId`，期间新提交的行 id 更大留到下一批，**不重不漏**）；摘要失败不推进 uptoId、置 dirty，自愈重试。
保真：`agent_message` 原值**永不删**；Redis 只存派生视图，丢了即从第一条重建（无摘要回放，安全降级）；`LlmConversationSummarizer` 一次返回 `{summary,keyData[]}`，`FidelityAssurance` 断言关键数字/日期出现在 summary，缺失则回填 `【数据点保留：…】` 或记观测属性 `compress.dropped-numbers`，绝不静默丢数。

### 6.3 P3 工具结果级压缩升级（Stage B）

- **归档点**：`ToolCallExecutor.execute/executeBypass` 中 `delegate.call(...)` 拿到完整 raw、`limitToolResult` 截断**前**调用 `ToolRawArchiver.archive`（该点是全链路唯一能取到 >1200 原始串的位置；DAG 的 `InMemoryToolResultStore` 存的是 guard 截断后值，不可用）。1200 硬截断保留作最后安全网，模型侧摘要基于 ≤1200 的 raw 生成，原值在 `agent:toolraw:*` 可查。
- **保真摘要**：Serial/Parallel 的 `ResultCompressor` 与 DAG 的 `LlmCompressor`(去 stub) 统一切到 `compressChatClient`，输出 JSON `{summary(≤L), numbers[], entities[], truncated}`；`FaithfulCompressor` 用 `KeyDataExtractor` 从 raw 抽数值回读断言，缺失记观测；失败一律降级 `TruncateCompressor`。
- planner 层 50/200/400 字截断**保留**（跨轮 planner 视图，非本轮保真对象），魔法常量收敛引用 `TemplateConstants`。
- 可选 `ToolRawDebugController`（`tool-raw.debug-enabled` 门控）按 cid 查原值。

### 6.4 小模型装配（P2 引入，P2/P3 共用）

DashScope MaaS OpenAI 兼容端点，压缩模型**同端点换 model 名**（qwen-plus → qwen-flash/qwen-turbo，无日期后缀更稳）。
`ChatModelConfig` **同处接管主模型 + 压缩模型**（否则 `OpenAiChatAutoConfiguration` 因我们新增 ChatModel 而退避）：`@Bean @Primary mainChatModel`(复用 `OpenAiHttpConfig.customOpenAiApi` + 连接池，还原 spring.ai 主模型行为，`setObservationConvention` 保 Langfuse 命名) + `@Bean compressChatModel`（defaultOptions 来自 `CompressModelProperties`；provider=inherit 复用主端点/api-key，custom 时 `OpenAiApi.builder()` 且复用 `OpenAiHttpConfig` 提为包可见的 `restClientBuilder()/webClientBuilder()` 连接池工厂，避免重造）+ `@Bean compressChatClient`。
压缩调用点统一 `CompressionObservation.run(SUBAGENT_COMPRESS, task, () -> …)` 打标记（Langfuse 生成名 `subagent-compress-<tool>-chat` 与既有约定一致）。

### 6.5 Redis key 总表

| Key | 类型 | 内容 | TTL/清理 |
|---|---|---|---|
| `agent:conv:{cid}:mem` | String | `Mem` JSON | 默认 7d，读写滑动续期 |
| `redis:agent:conv:{cid}:lock` | Redisson RLock | 压缩互斥 | lease 60s |
| `agent:conv:active` | Set | 活跃会话索引(cid) | 写回合刷新；供 sweeper |
| `agent:conv:{cid}:dirty` | String | 压缩待补标记 | sweeper 消费后清 |
| `agent:toolraw:{cid}:{tool}:{ts}-{rand}` | String | `{toolName,args,raw,createdAt}` | `tool-raw.ttl` 24h；归档端点 purge 前缀 |

序列化：`StringRedisTemplate` + 项目 ObjectMapper（与 `RateLimitPolicy` 同款惯例，值即 JSON 串，避免 GenericJackson 类型头噪音）。

## 7. 关键时序

**读回放（请求主链，同步）**：Controller/AiService → `ConversationReplayService.replay(cid,userId)` → `RedisConversationMemoryStore.read`(无则空) + `AgentMessageMapper` 取 `id>uptoId` 尾部窗口 → `Phase1PromptAssembler` 拼 `[System]+[摘要?]+[完整]+[User]`。

**写后投递（事务边界）**：`recordTurn` afterCommit → `ConversationCompressionDispatcher` → 组 `CompressionTask(cid,userId)` → `compressExecutor.execute`（AbortPolicy 拒绝→置 dirty）。

**压缩批处理（后台线程）**：`CompressTaskLockGuard` 加锁(失败→dirty 退出) → `CompressionOrchestrator`：`LoadProber` 取载荷 → `HybridPressurePolicy` 判（不足→跳过）→ `TailBatchSelector` 切批 → `LlmConversationSummarizer` 摘要 + `FidelityAssurance` 断言回填 → `store.update(new Mem)` → tail 已前进则最多追 2 次；finally 解锁。

**工具调用归档（P3）**：`ToolCallExecutor.execute` → `delegate.call` 得完整 raw → `RedisToolRawArchiver.archive`（截断前）→ 原 `limitToolResult` → 策略 `FaithfulCompressor` 出保真摘要喂模型。

## 9. 评测与验证体系（用户拍板：确定性断言 + 离线比对；judge 接口预留不开）

### 9.1 评测数据（三类来源）

| 数据源 | 用途 | 构造 |
|---|---|---|
| **金样本集 golden set** | 保真断言主战场 | 手工构造"满载事实"的对话轮/工具结果：金额、ID、百分比、日期、数量、专名混杂（如 10 条博客阅读量 1200/5000、7 折券核销率 92%…），附**期望保留关键数据清单**作金标准 |
| 真实 trace | 反映真实分布 | 复用现有 Langfuse dataset 与 `md/agent/json/trace-*.json`，抽真实多轮/工具调用样本 |
| 变异扰动 | 抗脆弱 | 对 golden 做 emoji/单位/超长串/截断变异，验证抽取器与断言不崩 |

### 9.2 数据比对（三层次，能确定性的全断言化）

核心原则：**把"语义是否变了"降维成"可断言的事实集合是否变了"**；只有确定性判不了才上 LLM judge。

- **L1 数值/事实比对（确定性、CI 可跑）**：原文与摘要各经 `KeyDataExtractor` 抽 keyData，断言 `原文keyData ⊆ (摘要keyData ∪ 仍完整可查的原值keyData)`；规范化比较（去千分位/单位差异：`1,200`=1200）。工具层直接对 `agent:toolraw` 原值同断言。**dropped 恒 0 = 保真底线**。
- **L2 结构/成本比对**：before/after input tokens（Langfuse `gen_ai.usage.input_tokens`）削减率、每会话压缩次数、近期未压完整窗口轮数（看"压得值不值"，也是"缺哪补哪"自检）。
- **L3 语义比对（judge 接口预留，本轮不开）**：两类题 (a) **摘要忠实性**——judge 读原文+摘要判事实冲突/关键点遗漏；(b) **答案一致性**——同一问分别用"无摘要全量历史"与"[摘要]+近期"作上下文，判语义等价。接口占位，后续接现有 Langfuse evaluator/Experiment。

### 9.3 上下文核心指标集

| 指标 | 含义 | 判断 |
|---|---|---|
| 输入 token / 削减率 | `phase1-chat` input tokens 压缩前后，跨轮次**单调性** | 滚雪球压平、削减率随轮数上升 |
| 记忆检索有效 | 跨轮指代题（"我刚才问哪个城市"）答对率 | 多轮记忆从 0→1 的金指标，答对=生效 |
| dropped-keyData | 摘要丢弃的关键数值数 | 恒 0，>0 即观测告警 |
| judge 忠实度 | L3(a) 分数 | ≥ 设定分（开 judge 后启用） |
| 完整率 | 近期未压窗口轮数 / keep-recent-turns | "缺哪补哪"自检 |
| 旁路 P95 | 压缩是否影响请求延迟 | 隔离池下应≈0 |
| 压缩成本 | 每会话摘要 token（qwen-flash 档） | 计入降本收益比 |

### 9.4 比对基建（可执行）

- **压缩埋点 AgentField**：每个压缩点打 `compress.{kind}.{input-keydata,summary-len,dropped-numbers}` 属性（keyData 低敏），进 Langfuse/观测作为 L1/L2 取数源；sanitize 沿用 `AttributeSanitizer`。
- **离线比对脚本**（仓库内 `md/agent/tools/compare-compression.sh|py`，非运行时代码）：入参 trace json 或 `(conversationId)`，读 Redis `mem`/`agent:toolraw` + DB `agent_message` → 抽 keyData → 跑 L1 集合断言 → 输出报告 `dropped / 削减率 / 窗口完整率 / 逐条 diff`。提交/CI 前可对 golden set 回归。
- **单测**（各阶段已列）：抽取器、断言器、worker 锁/追平、压缩器降级、store 原子/TTL。

### 9.5 各阶段落地验证点

- **P1**：双模新会话"介绍长沙天气"/"我刚才问哪个城市"→能答"长沙"（记忆检索生效）；Langfuse `phase1-chat` 输入含历史；`agent_message` 每回合 +2；`SPRING_AI_CHAT_MEMORY` default 桶仍 0。单测（P1 已实现，2026-09-03）：新增 `ConversationReplayServiceImplTest`/`AgentRoleReplayMessageMapperTest`/`Phase1PromptAssemblerTest`/`ReplayBudgetTrimTest`，`AiServiceImplE2ETest` 适配（4 参重载 + 历史传递用例，共 27 案全绿）。

## 10. 全面异常矩阵与降级（压缩是旁路：任何异常不得阻断请求主链 fail-open）

| # | 异常 | 影响面 | 降级动作 | 自愈/观测 |
|---|---|---|---|---|
| 1 | 小模型超时/429/4xx/网络 | P2 摘要 | 不推进 uptoId、置 dirty | sweeper + 下个写回合重试；span 记 `compress.error` |
| 2 | 返回非 JSON/字段缺 | P2/P3 | 按失败处理同上 | 同上 |
| 3 | 返回 JSON 但 keyData 缺漏 | P2/P3 保真 | 摘要尾回填 `【数据点保留】`（容量允许） | `compress.dropped-numbers`>0 告警；原值仍 DB/Redis 可查 |
| 4 | 摘要自身超长(二次超预算) | P2 | 二次收敛压缩 或 扩大近期窗口 | 压缩比例封顶防抖振 |
| 5 | Redis 读异常/丢失/过期 | P2 回放 | `Mem` 缺失→uptoId=0、摘要空→回退 DB 全量尾部窗口(P1 行为) | 下个写回合重建摘要 |
| 6 | Redis 写异常 | P2 | 不推进、置 dirty | sweeper 重试 |
| 7 | 锁获取失败/超时 | P2 | 丢弃本次（幂等） | dirty 留待追平 |
| 8 | 压缩中并发新回合写入 | P2 | 只压 (uptoId, 批尾]，新行留批 | 追平循环封顶 2 次防活锁 |
| 9 | 摘要撕裂/半截 | P2 | `Mem` 单 key 原子 SET，读恒成对快照（机制上消除） | 观测告警防回归 |
| 10 | worker 崩溃/进程重启 | P2 | 任务丢失但 dirty/active 在 | sweeper 兜底自愈 |
| 11 | 工具归档失败(P3) | 原值丢失 | 仅 log.warn，**不阻断工具调用** | 1200 硬截断仍兜底进模型 |
| 12 | 会话归档/删除 | P2/P3 | `ConversationMemoryCleaner.purge(cid)` 清 mem+toolraw | sweeper 扫 status!=0/TTL；无删除端点则预留接口 |
| 13 | 新增 ChatModel 注入歧义 | 装配期 | `ChatModelConfig` 同处接管 `@Primary` 主 bean 还原 auto-config | 启动自检 |

关键路径异常（1/2/5/6/7/11）必须配单测；所有旁路异常不许吞掉主链异常、不许污染请求线程 ThreadLocal（cleanup TaskDecorator）。

## 11. 代码风格铁律（实现时对照）

- 类 ≤ 一个核心职责；超过即拆（本设计已拆；实现中再发现上帝方法同样外置）。
- 组件间经**接口**协作；实现类不互相 import 具体类。
- 禁止布尔透传/裸参透传，跨层用值对象。
- 所有压缩调用走 `CompressionObservation.run`，不再手写 mark/clear try-finally。
- 每个对外端口配一个真实实现的单测；编排类配伪策略（stub）单测。
