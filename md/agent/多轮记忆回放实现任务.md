# Agent 多轮记忆回放 — 实现任务（拆分给独立会话）

> 版本：2026-09-03 交接稿
> 背景：本任务是"上下文压缩子系统"（见 `上下文压缩子系统设计文档.md` §0）P1 记忆回放地基，为不与压缩实施相互抢占上下文，**拆给独立 Claude 会话实现**。
> 依赖关系：压缩子系统（另一会话/后续）会**复用本任务建立的 `ConversationReplayService`** 作为摘要+近期完整的读取点——包路径/方法名/语义是跨会话契约，勿自由改名。
> 目标分支：后端 `feature`（remote `github`，SSH）。

## 一句话目标

现在 AI 对话每次都把 `[系统提示 + 你这条问题]` 单独发给模型，**前面轮次的历史从不回灌**——用户实测"告诉它一个事实，下句问它，它自编答案"。本任务让 SSE 请求把本会话**最近 N 轮历史**拼进模型输入，让模型能记住用户前面说的话。

- 历史落库完整：`agent_message` 表每回合写 `user`+`assistant` 两行（role 仅这两种），**只被前端历史列表读取、从不喂模型**。表字段：`id`(自增)/`conversation_id`/`user_id`/`role`/`content`/`created_at`。

- `mapper/AgentMessageMapper` 是纯 BaseMapper，无尾部窗口查询；可复用 `AgentHistoryServiceImpl.listMessages` 的 LambdaQueryWrapper 风格。
- system 模板无当前时间——**不要做日期/时间注入**（需求方明确不需要）。
- `hook/impl/SensitiveWordHook` 已默认关闭（`agent.hook.sensitive-word.enabled=false`），**别改它**。

## 改动清单（文件级建议）

1. **配置**：`ReplayProperties`（`agent.replay.enabled=true`、`keep-recent-turns=6`）——硬上限防 token 涨。
2. **新类 `ConversationReplayService`**（`com.hmdp.agent.history` 或就近）：
   方法 `List<org.springframework.ai.chat.messages.Message> recentMessages(Long userId, String conversationId, int windowTurns)`
   ——按 `(conversationId, userId)` 查 `agent_message` 取尾部 `2*windowTurns` 条（`orderByDesc(id).last("LIMIT ...")` 再 reverse 升序），role 映射 `"user"→new UserMessage(content)` / `"assistant"→new AssistantMessage(content)`；无消息返回空。
   **这是与"上下文压缩子系统"的契约读取点，方法名与语义勿自由改名。**
3. `stream/StreamingChatInvoker.streamWithRetry` 增加 `List<Message> historyMessages` 参数（置于 system 与当前 user 之间），**重试循环内历史固定不变**，错误回喂仍只追加当前 user。
4. `service/impl/AiServiceImpl.doChatWithToolcall` 异步段调 invoker 前读历史；**读历史必须 fail-open**（DB 异常 catch 返回空列表 + log.warn，不能阻断对话）。
5. `stream/SseResponseProcessor`：PASS/REPLACE 落库挪到 `route()` / complete **之前**。
6. **测试**：新增 `ConversationReplayService` 单测（尾部窗口/升序/role 映射/空会话/userId 过滤）；适配已有 SSE 测试。
