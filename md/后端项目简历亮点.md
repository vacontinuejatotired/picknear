## 项目职责

电商点评类后端项目（Spring Boot 3.4 + MyBatis-Plus + Redis + RabbitMQ），涉及秒杀、AI 对话、店铺检索等业务。个人负责核心模块设计与实现。

## 难点攻克

**1. 秒杀库存扣减不能超卖，也不能重复下单** — 最初用数据库行锁扣库存，QPS 一上去就死锁。方案改为两条腿走路：下单请求先走 Redis Lua 脚本，一条命令内完成"库存 > 0"校验 + "是否已下单"去重 + 库存预扣，全部通过才放行；订单落库和实际扣库存交给 RabbitMQ 异步处理，消费失败走死信队列、最多重试 3 次。类名：`MqVoucherOrderServiceImpl`、`seckillScript`（Lua）、`RedisIdWorker`（ID 预生成队列防热点）。结果：扣库存瓶颈从 MySQL 行锁移到 Redis 单线程，压测未出现超卖。

**2. 双 Token 失效后无法撤销，且临期刷新请求密集** — 普通 JWT 签发后不能踢人，所有用户临期时同时刷新会把 Redis 打满。方案：RefreshTokenInterceptor（order=0）拦截全部请求做 Token 透明续期 + LoginInterceptor（order=1）做登录兜底。签发时将 version 写入 JWT claims，Redis 存最新版本号，Caffeine 本地缓存做快速拒绝——版本不匹配在内存层直接拦截，不用查 Redis。临期刷新用分布式锁防并发，过期刷新不 bump 版本号、直接用 SET 覆盖。类名：`RefreshTokenInterceptor`、`AuthServiceImpl`、`JwtUtil`、`tokenValidVersionCache`（Caffeine）。结果：踢人操作毫秒级生效，临期刷新无 Redis 热点。

**3. AI 调接口不能失控** — 聊天场景下 AI 可能生成恶意指令或越权操作。做法：`PromptHookChain` 对用户输入做注入关键词检测；工具调用由 `GuardedToolCallback` 统一包装，过 4 个 Policy（`HighRiskListPolicy` 精确匹配黑名单 → `PatternMatchPolicy` 正则 → `ConfirmToolPolicy` 需确认 → `RateLimitPolicy` Redis 频率上限），任一拦截即阻断。工具方法再加 `@RequiredDataPermission` AOP 切面，校验当前用户操作的数据是否归属自己。所有工具通过 `@TargetTool` 注解自动注册到 `ToolBeanCollector`，新人加工具只需加类、无需改配置代码。上线至今未发生越权操作。

**4. 热点店铺缓存失效会打穿到 DB** — 第一个请求发现缓存过期后，不是所有线程都去查 DB，而是抢到分布式锁的线程异步重建缓存、返回旧数据，没抢到的直接返回旧数据。空数据也缓存占位符（2 分钟过期）防穿透。用户信息做了三级缓存：Caffeine 本地（毫秒级）→ Redis Hash（批量 pipeline 写入）→ MySQL，`BatchLoadCache` 每 2 秒定时批量加载。类名：`CacheClient.queryWithLogicExpire`、`BatchLoadCache`、`CaffeineConstants`。结果：缓存击穿时 DB 查询量不升高。

## 面试官追杀三问

1. 你说 Lua 脚本原子校验库存+去重，这把脚本部署在 Redis 上还是每次请求发送脚本内容？如果集群部署，库存数据在哪个节点？
2. Token version 存在 Caffeine 里，Caffeine 是本地缓存，不同实例的版本怎么保证一致？Redis 里改了版本、Caffeine 没失效怎么办？
3. `GuardedToolCallback` 包装了 `@TargetTool` 的所有工具，如果某个工具方法抛异常了（NPE 或 JSON 序列化失败），外层怎么处理的？`RateLimitPolicy` 的 Redis 计数过期不准怎么办？
