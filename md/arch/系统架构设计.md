# 系统架构设计

## 1. 技术栈

| 层 | 技术 |
|---|---|
| 应用 | Spring Boot 3.4.4 / Java 17 |
| 数据访问 | MyBatis-Plus / MySQL |
| 缓存 | Redis / Caffeine |
| 消息 | RabbitMQ |
| 文件 | 本地存储 / 阿里云 OSS |
| AI | Spring AI / DashScope |
| 鉴权 | JWT 双 Token |

## 2. 包结构

```text
com.hmdp
├── common/      通用缓存、锁、幂等和上下文
├── config/      MVC、Redis、RabbitMQ、Redisson、OSS 等配置
├── interceptor/ Token 刷新与登录拦截
├── exception/   业务异常与全局异常处理
├── auth/        认证、Token、验证码、密码和登录策略
├── user/        用户资料、头像、签到和账号查询
├── shop/        商铺和店铺类型
├── voucher/     优惠券、秒杀库存、订单和 MQ
├── content/     博客、评论、关注和 Feed
└── agent/       AI 对话、规划执行、记忆、安全、测评和观测
```

辅助包包括 `dto`、`entity`、`enums`、`mapper`、`aspect`、`annotation` 和 `utils`。

## 3. 域职责

| 域 | 核心职责 |
|---|---|
| `auth` | 验证码、密码登录、双 Token、刷新、登出和改密 |
| `user` | 用户资料、头像、签到、账号查询 |
| `shop` | 店铺查询、类型、缓存和距离排序 |
| `voucher` | 券管理、秒杀库存、订单落库和 RabbitMQ |
| `content` | 博客、评论、关注、Feed 推送和查询 |
| `agent` | SSE 对话、规划执行、工具、记忆、安全和观测 |

详细边界：

- 认证域见 [认证与登录设计](../auth/认证与登录设计.md)。
- Agent 域见 [Agent 模块入口](../agent/README.md)。

## 4. 请求主链

```text
HTTP Request
  -> MvcConfig 注册的拦截器
     -> RefreshTokenInterceptor
     -> LoginInterceptor
  -> Controller
  -> Domain Service
  -> Mapper / Redis / MQ / OSS
  -> Result
```

### 4.1 RefreshTokenInterceptor

负责：

1. 提取 `authorization`；
2. 校验 Access Token 和版本；
3. 加载用户上下文；
4. 临期或过期时刷新双 Token；
5. 写回响应头与 refresh Cookie；
6. 请求结束后清理 ThreadLocal。

### 4.2 LoginInterceptor

仅判断当前请求是否已获得用户上下文。需要登录的路径在刷新拦截器之后执行。

## 5. 认证链路

核心组件：

- `TokenService`
- `SessionContextService`
- `VerifyCodeService`
- `PasswordService`
- `LoginStrategyRegistry`

登录成功后：

- Access Token 通过 `authorization` 返回；
- Refresh Token 通过响应头和 httpOnly Cookie 返回；
- Redis 保存 Access、Refresh、validVersion、currentVersion。

刷新不 bump version；重新登录和改密会 bump version。

## 6. 秒杀链路

当前拆分：

```text
VoucherOrderController
  -> SeckillOrderService
  -> SeckillStockService
  -> VoucherOrderProducer
  -> RabbitMQ
  -> VoucherOrderConsumer
  -> VoucherOrderService
```

职责：

| 组件 | 职责 |
|---|---|
| `SeckillOrderService` | 秒杀流程编排 |
| `SeckillStockService` | Redis + Lua 原子扣减和回补 |
| `VoucherOrderProducer` | 发送订单消息 |
| `VoucherOrderConsumer` | 消费落库并处理幂等 |
| `VoucherOrderService` | 订单持久化与查询 |

库存与订单链路不再由单个 Service 同时承担生产和消费职责。

## 7. 缓存

缓存能力经 `CacheManager` 统一入口：

| 层 | 作用 |
|---|---|
| Caffeine | 本地快速缓存 |
| Redis | 分布式缓存和逻辑过期 |

缓存实现需要处理：

- 缓存穿透；
- 热点 key 重建；
- 逻辑过期；
- 空值缓存；
- 本地与 Redis 一致性。

## 8. 分布式锁

统一使用 `LockTemplate`：

- 锁值带所有者标识；
- 释放时校验所有者；
- 锁通过 `AutoCloseable` 释放。

业务代码不应继续新增手写 `setIfAbsent + delete`。

## 9. 幂等

`common.idempotent` 提供：

- `@Idempotent`
- `IdempotentAspect`

秒杀、下单等可重试入口应使用统一幂等能力，而不是各服务自行维护标记。

## 10. 内容与 Feed

`content` 域拆分：

| 组件 | 职责 |
|---|---|
| `BlogQueryService` | 博客查询 |
| `BlogPublishService` | 发布与更新 |
| `BlogLikeService` | 点赞 |
| `FeedPushService` | 新博客推送到关注者 |
| `FeedQueryService` | 游标分页读取 Feed |
| `FollowServiceImpl` | 关注关系 |

Feed 使用 Redis ZSet 保存时间戳游标，服务端从列表尾部获取最旧游标。

## 11. 文件上传

`FileService` 提供：

- 本地存储实现；
- OSS 实现。

实现由 Profile 选择，Controller 不直接依赖具体存储。

## 13. 横切约束

1. Controller 只做参数解析、鉴权后编排和响应组装。
2. 事务边界放在 Service 编排层。
3. Mapper、Entity 和 Redis 细节不直接泄漏到 Controller。
4. 跨域通用能力进入 `common`，不在各域重复实现。
5. 新增扩展点优先使用接口 + Spring 收集策略。
6. 当前架构与历史拆分过程分开维护；历史记录在 `report/`。
