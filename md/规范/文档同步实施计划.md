## 2. P0a —— 探针阶段（✅ 完成）

以临时探针验证 hook 接口真机行为，**结论已并入运维手册 §3**。结论要点：

1. `last_assistant_message` 完整携带上一轮回复全文 ⇒ 声明检测直接用它。
2. `systemMessage` 用户可见、不阻断、不续跑；标签前缀为 `Stop says:`。
3. `additionalContext` 在 Stop 上续跑一次，标签为 **`Stop hook additional context`**
   （**非**早期计划的 "Stop hook feedback"）。
4. **`additionalContext` 的续跑不产生第二次 Stop**；只有 `decision:"block"` 会二次 Stop（带 `stop_hook_active=true`）。
   ⇒ 阶段 B 防循环须靠内容键去重，不可依赖 `stop_hook_active`。
5. PostToolUse 上输出任何内容都会被注入（`additionalContext` 每次编辑刷屏 / `block` 渲染成 `blocking error`）
   ⇒ record 脚本必须恒定静默。
6. 宿主解释器链三者齐全（命中 MSYS2 python3 3.12）；VM 只有 `python3` 3.10。
7. 宿主 `E:\heima` 与 VM `/mnt/hgfs/heima` 共用同一 `.claude/doc-sync/`。

### 3.2 doc-map 初版规则

严格按规范 §3.1 的范围起步（不追求覆盖率达标）：

| rule id | tier | 覆盖 |
|---|---|---|
| `agent-api` | must | `agent/controller/**`、`agent/access/**` |
| `agent-protocol` | must | `agent/stream/**` |
| `agent-security` | must | `agent/guard/**`、`agent/hook/**`、`agent/permission/**` |

### 3.4 与初版计划的偏差（本阶段实际决定）

1. **新增 `doc_sync_selftest.py`**（计划外）：把九条验收里可确定性验证的部分固化成 62 项回归检查，
   无需 Claude 会话即可跑。
2. **`agent-protocol`、`agent-security` 两条规则为计划外拆分**：初版示例把 SSE 与安全都并进 `agent-api`，
   实际拆开后职责更清晰（协议/安全/接口三类各自的 required_docs 不同）。
3. **`md/ops/API接口文档.md` 未补 `source_of_truth`**（用户决定）：该文档 frontmatter 与内容补齐留作
   P0c 观察期发现的第一个真实待办，用它验证机制本身能发现漂移。
4. **`.claude/settings.json` 的命令加 `sh` 前缀**：规范 §8 要求 hook 一律经 `sh` 显式启动
   （hgfs 不保证执行位），与工作区根 settings 保持一致。
5. **`git ls-files` 必须加 `-z`**（实测踩坑）：不加 `-z` 时 git 对非 ASCII 路径做 C-quoting
   （`"md/agent/Agent\344\270\212…"`），中文文档路径会全部匹配失败。库已修正并配 `core.quotepath=false`。

**启用准入**：`gates.mode=observe` 上线 ≥2 周 → 切 `enforce` + 开分支保护。

**验收**：开主题分支做 5 个测试 PR：
① must 命中无文档 → enforce 红、observe 绿+summary 违规表；
② 补 required doc → 绿；
③ 勾豁免+理由+新打标签 → 绿+summary"豁免记录（含 head SHA）"；
④ 勾豁免无理由 → 红；
⑤ 先打标签后推送新提交 → 红（须重打标签确认）。

> ①②④⑤ 的判定逻辑**已在 P0b 用临时仓库实测通过**（见 §3.3），P1 需在真实 GitHub PR 上复验。
