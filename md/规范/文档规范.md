# 文档规范

本文是 PickNear 文档治理的唯一事实源。入口文件只保留触发和跳转，不复制完整规则。

## 1. 基本原则

1. 代码、配置、运行时行为和可执行测试是事实证据；文档冲突时先核对它们，再更新文档。
2. 能推导的信息不要求人工填写，不能检查的规则不设为强制规则。
3. 一个事实只保留一个当前事实源，其他文档只链接，不复述。
4. 默认不新增文档，优先修改已有文档。
5. 历史材料默认依赖 Git，不建立长期 `archive/` 目录。

## 2. 修改入口

修改 `md/**` 前必须读：

1. 本文；
2. 目标模块的 `README.md`；
3. 与任务直接相关的一个主要文档。

找不到任务路由时，先在模块 README 和现有文档中搜索，不因为“没找到”就新建文档。

## 3. 目录与类型

模块始终作为一级目录，类型不再作为全局一级目录。

```text
md/
  README.md
  agent/
    README.md
    Architecture.md
    runbook/
      快速开始与配置.md
    observability/
      xxx.md
    evidence/
      trace.json
```

类型由路径和用途表达，不单独维护 `type` 元数据：

| 位置 | 含义 |
|---|---|
| 模块 `README.md` | 模块概览、主题索引和任务路由 |
| 模块根目录下的 Markdown | 当前架构、契约或设计文档 |
| `runbook/` | 操作、启动、验证和排障步骤 |
| `observability/` | 观测专题文档 |
| `evidence/` | trace、截图、原始日志等非文档证据 |

`evidence/` 不进入当前索引，不参与默认阅读。

## 4. 状态

状态只保留三个值：

| status | 含义 |
|---|---|
| `draft` | 草稿，不作为默认依据 |
| `current` | 当前有效事实，必须可从模块 README 到达 |
| `legacy` | 旧文档或未迁移文档，不进入当前索引 |

被替代的 `legacy` 文档使用 `superseded_by` 指向新文档。旧内容迁移完成后直接删除，不建立 `archive/`。

未声明状态的旧文档按 `legacy` 处理。新文档和本次修改到的文档必须声明状态。

## 5. 元数据

只保留能驱动迁移、阅读和安全检查的字段：

```yaml
---
status: current
source_of_truth:
  - picknear/src/main/resources/application.yaml
superseded_by:
---
```

字段规则：

1. `status` 必填，只允许 `draft`、`current`、`legacy`。
2. `source_of_truth` 仅在文档陈述代码、配置或接口事实时填写，路径统一相对仓库根目录。
3. `superseded_by` 仅在文档被替代时填写，路径相对仓库根目录。
4. 更新时间由 Git 推导，不人工维护。
5. 文档类型由路径推导，不人工维护。
6. 标题、主题和阅读时机由模块 README 的任务路由维护，不在每份文档重复声明。

根索引和模块 `README.md` 不要求元数据。

## 6. 索引与任务路由

索引只分为三层：

```text
md/README.md
  -> 只列模块和模块 README

md/<module>/README.md
  -> 主题索引
  -> 任务路由

专题文档
  -> 稳定章节可提供锚点
```

模块 README 必须包含：

1. 一段模块定位；
2. 当前文档的主题索引；
3. 按任务读取的路由表。

主题索引示例：

| 主题 | 当前文档 |
|---|---|
| 执行链 | `执行链路.md` |
| 安全与审批 | `安全审批.md` |
| 运行手册 | `runbook/快速开始与配置.md` |

任务路由示例：

| 我要做什么 | 读取 |
|---|---|
| 本地启动和验证 | `runbook/快速开始与配置.md` |
| 修改工具依赖 | `执行链路.md#工具依赖` |

规则：

1. 任务路由只放在模块 README，不放到根 README 或每份专题文档。
2. 稳定章节使用锚点；锚点不稳定时先链接整份文档。
3. 新增、删除或重命名当前文档时，必须同步模块 README。
4. `legacy` 文档不得出现在当前主题索引和任务路由中。

## 7. 按需加载

默认读取预算：

1. 读 `md/README.md`，只确定模块。
2. 读模块 README，只确定主要文档和一到两个章节。
3. 不默认读取整份长文档，不递归读取所有相关文档。
4. 超过 300 行的文档必须提供章节地图。
5. `legacy` 和 `evidence` 不参与默认阅读。

## 8. 新建、合并与删除

1. 新建文档前必须说明为什么现有文档无法承载。
2. 新文档必须声明 `status`，并同步模块索引和任务路由。
3. 设计实施完成后，将有效内容合并进架构、契约或 Runbook。
4. 完成型交接稿、一次性排障稿和原始证据不得长期留在当前文档目录。
5. 新增、删除或重命名当前文档时，必须修复引用和入口。
6. 不允许借文档整理之名进行无关重命名、移动或批量格式化。

## 9. 迁移规则

1. 新文档和本次修改到的文档必须符合本规范。
2. 模块 README 被重写后，其中列出的文档必须全部满足 `status: current`。
3. 未迁移文档保持 `legacy`，逐步合并或删除。
4. 模块迁移采用逐模块方式，不要求一次性全量重写。

## 10. 最小检查

文档检查脚本只做确定性检查：

1. Markdown 相对链接目标是否存在。
2. `status: current` 文档是否能从所属模块 README 到达。
3. 任务路由引用的文件是否存在。
4. `superseded_by` 指向的文件是否存在。
5. `status` 是否合法。

脚本不判断文档质量、不猜类型、不检查人工日期，也不判断某段内容是否“像交接稿”。

## 11. 完成条件

完成文档任务前只回答三个问题：

1. 当前文档入口和链接是否正确？
2. 关键配置、类名和状态是否对照事实源？
3. 为什么必须新增文档？

三个问题无法回答时，任务不得标记为完成。
