# 文档同步规范

本文是「代码改动 → 文档同步」机制的**规范**：定义什么是"同步"、怎么判定、怎么豁免。
实现、脚本与运维操作见 [文档同步运维手册](../ops/文档同步运维手册.md)；阶段与验收见 [文档同步实施计划](文档同步实施计划.md)。

> 原则：先定义"同步"再谈检查；能确定性检查的硬查，语义判断交给抽样审计；
> 一切拦截动作都要求"更新文档或显式决策"二选一，**不允许静默忽略**。

---

## 1. 术语（本规范内固定含义）

| 术语 | 含义 |
|---|---|
| doc-map | 代码路径↔文档路径映射与规则文件（`scripts/docs/doc-map.json`） |
| rule（规则） | doc-map 中一条映射：`code globs → required/optional docs + tier + owner` |
| tier | 规则级别：`must`（必须同步）/ `should`（建议同步）；无匹配规则的文件属"无需同步" |
| 初筛（path screening） | 用路径命中做第一层判断——**只用来要求"显式决策"，不是文档同步的充分条件** |
| 内容一致性检查 | 可确定性验证的检查（`source_of_truth` 时效、生成物 drift、链接、索引完整性） |
| 语义审计 | 用 LLM 抽样比对代码 diff 与文档内容的失真判断（**只报告，不阻断**） |
| 归属（attribution） | 判断"这次改动是谁改的"：hook 用本会话 transcript 记录；CI 用 git 事实 |
| 声明（Docs-Impact） | Claude 在回复**末行**输出 `Docs-Impact: none — <理由>` 表示确认无需更新文档 |
| 豁免（exemption） | PR 通道的显式放行：PR 模板勾选+理由，或 `docs-exempt` 标签；全部记录 |
| 拦截（violation） | must 规则命中且无文档改动且无豁免/声明的事件（hook block / CI fail） |
| 覆盖率 | 被规则覆盖的代码文件数 ÷（`git ls-files` 代码文件全集 − exclude − unmanaged 命中数） |
| 孤儿文档 | `status: current` 但不归属于任何规则文档集的文档（validate 列 INFO） |
| gates.mode / hook.mode | 两层各自的运行模式：`observe`（只报告）/ `enforce`（拦截）；`remind`（只提醒）/ `block-must`（must 可阻断） |

## 2. 范围与非目标

**范围**：`E:\heima` 工作区内的两个 git 仓库（picknear 后端、frontend 前端）＋工作区级 Stop hook；
覆盖"代码改动→文档同步"的 **提醒（hook）→ 守门（CI）→ 审计（定期）** 三层。

**非目标**（明确不做）：

1. 不自动撰写业务文档内容——机制只做提醒、守门、报告。
2. CI 不做语义正确性判定（无 LLM 调用），语义交给定期审计抽样。
3. 不管理第三方目录（`superpowers/`、`node_modules/`、`target/`）。
4. 不覆盖其他 AI 工具（Reasonix/Trae/Codex）的会话内提醒——它们的改动由 CI 层兜住（`AGENTS.md` 同步写入规则）。
5. 不迁移/重写历史文档；MVP 不做 AST 级 API diff。
6. 定期审计不作为阻断层。

## 3. 同步标准（分级判定规则）

**"同步"的定义**：合入 master 时，改动要么已反映到指定文档（同一 PR 内完成），
要么存在一条被记录的豁免/声明。**"路径命中"本身不等于"需要同步"**——路径命中只触发"显式决策"义务。

### 3.1 按文档类型分级

| 文档类型 | 后端位置示例 | 触发面（代码） | 默认 tier |
|---|---|---|---|
| API 文档 | `md/ops/API接口文档.md` | controller 路由/方法签名/请求响应 DTO 字段 | must |
| 配置文档 | `md/ops/*`（部署/环境相关章节） | `application*.yaml`、`docker-compose.yml`、`Dockerfile`、`.env` 键增删改 | must |
| 协议文档 | `md/agent/SSE后端实现规范.md` | SSE 事件类型/字段、MQ 消息契约 | must |
| 架构文档 | `md/arch/`、`md/<module>/**` | 包结构、执行链、编排/内部服务结构 | should |
| 运维文档 | `md/ops/CI流水线.md`、日志/可观测文档 | CI 流水线、部署链路、日志行为、监控端点 | 行为变化=must；补充说明=should |
| 安全文档 | `md/agent/Agent安全与审批设计.md`、`md/auth/` | 认证/授权/限流/工具审批（ToolGuard）行为 | must |
| 用户/前端方案文档 | `frontend/docs/**`、`frontend/CLAUDE.md` | 用户可见行为、组件契约、约定变更 | should（M2 起） |

### 3.2 三值分级总则（示例即判定用例）

- **must**：会让已有文档**失真**的改动。
  例：给 `ChatController` 加一个接口参数、`application.yaml` 新增配置键、SSE 事件多一个字段、ToolGuard 放行规则变化。
- **should**：文档描述的内部结构变了但无对外事实变化。
  例：`MultiRoundOrchestrator` 重构内部循环、工具类拆分重命名。
- **无需同步**：纯重构（无行为变化）、测试、格式化、注释、修复"恢复文档已述行为"的 bug、生成物目录。

### 3.3 判定示例（边界仲裁）

| 改动 | 判定 | 理由 |
|---|---|---|
| 改 controller 方法签名 | must | API 文档描述的契约失真 |
| 给 `application.yaml` 加配置键 | must | 部署指南的配置表失真 |
| `stream/` 里新增 SSE 事件常量 | must | 协议文档的事件表失真 |
| `guard/` 放行规则调整 | must | 安全文档描述的审批行为失真 |
| 重构 `orchestration/` 内部循环，对外行为不变 | should | 内部结构变化，建议核对架构文档 |
| 新增单元测试、格式化、改注释 | 无需同步 | 不影响任何文档陈述的事实 |
| 修 bug 使行为**回到**文档已描述的状态 | 无需同步 | 文档本就正确 |

> 不明确的先在 PR 里提问，不臆断。判定示例随实际争议持续补充。

## 4. doc-map（schema 与治理）

**文件**：`scripts/docs/doc-map.json`（后端）。**选 JSON 而非 YAML**：
Python(stdlib `json`)/Node(原生)零依赖可解析，避免引入 PyYAML 依赖使 CI 与本地不一致。

### 4.1 schema

```json
{
  "version": 1,
  "repo": "picknear",
  "owner": "Ntwitm",
  "updated": "2026-10-11",
  "hook":   { "mode": "remind" },
  "gates":  { "mode": "observe" },
  "coverage_threshold_pct": 70,
  "orphan_exempt": ["md/report/**", "md/规范/**"],
  "rules": [
    {
      "id": "agent-api",
      "tier": "must",
      "owner": "Ntwitm",
      "last_verified": "2026-10-11",
      "code": ["picknear/src/main/java/com/hmdp/agent/controller/**"],
      "required_docs": [
        { "type": "api",      "path": "md/ops/API接口文档.md" },
        { "type": "protocol", "path": "md/agent/SSE后端实现规范.md" }
      ],
      "optional_docs": ["md/agent/**"],
      "note": "对外接口与 SSE 协议；至少更新 required_docs 中与改动面相关的一项"
    }
  ],
  "unmanaged": ["picknear/src/test/**"],
  "exclude": ["**/*.md", "**/target/**", "**/logs/**", "**/.claude/**"]
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `repo` | 仓库名，validate 会与本仓库目录名核对（防加载错仓库的 map） |
| `hook.mode` | `remind`（只提醒）\| `block-must`（must 可阻断） |
| `gates.mode` | `observe`（只报告）\| `enforce`（拦截） |
| `coverage_threshold_pct` | 覆盖率告警阈值（WARN，不阻断） |
| `orphan_exempt` | 免于孤儿检测的文档 glob（如 `md/report/**`） |
| `rules[].tier` | `must` \| `should` |
| `rules[].code` | 触发面 glob（**仓库根相对 POSIX**） |
| `rules[].required_docs` | 必须至少动一项的文档；`type` 仅为人读标注 |
| `rules[].optional_docs` | 建议核对的文档（validate 不强制其存在性） |
| `unmanaged` | 明确不纳入覆盖率分母的路径（实体/ mapper/测试等） |
| `exclude` | 完全排除的路径；**`**/*.md` 必列**（文档不算代码改动） |

### 4.2 glob 方言（唯一实现）

**方言固定为"仓库根相对 POSIX + gitignore 风格"**，由 `doc_sync_lib.glob_match` 单点实现，
**hook / CI / 审计共用同一匹配器，禁止各写一套**。

| 模式 | 语义 |
|---|---|
| `**` | 匹配任意层级（含 0 层） |
| `**/` | 匹配零个或多个目录层级 |
| `*` | 单层内任意字符（不跨 `/`） |
| `?` | 单层内一个字符 |

示例：`a/**` 匹配 `a/b/c.py` 与 `a/x.py`，**不**匹配 `aX/b.py`。

### 4.3 治理规则（`doc_sync_check.py --validate` 每次必跑）

| # | 检查 | 级别 |
|---|---|---|
| 1 | schema 合法：version / 规则 id 唯一 / tier 枚举 / globs 非空 | FAIL |
| 2 | 每条 rule 的 `code` glob 至少命中 1 个 git 跟踪文件（防规则腐烂） | FAIL |
| 3 | `required_docs` 的 path 存在且被 git 跟踪 | FAIL |
| 4 | 时效：rule 的 docs 末次提交早于 code 末次提交 → 进"待核对"报告 | 报告/WARN |
| 5 | 覆盖率（分母已排除 exclude 与 unmanaged）< `coverage_threshold_pct` | WARN |
| 6 | 孤儿文档：模块设计类 current 文档不在任何 rule 的 docs 集合中 | INFO |
| 7 | 跨仓库归属：CI 只加载本仓库 map 并校验 `repo` 字段 | FAIL |

文件全集一律取 **`git ls-files`**（不用文件系统枚举——工作区里有空目录残骸与非跟踪文件）。

**治理流程**：改 doc-map 同步 `updated` 字段；季度审计复核孤儿清单与"待核对"报告。
**doc-map 为主登记、frontmatter `source_of_truth` 为被校验方**——同一事实只在一处登记。

## 5. 声明协议（Docs-Impact）

Claude 在**回复的最后一个非空行**输出：

```
Docs-Impact: none — <非空理由>
```

- 分隔符接受 `—`（em dash）、`–`（en dash）、`-`（hyphen）。
- **理由必须非空**；`Docs-Impact: none` 裸声明**不生效**。
- **锚定末行**：声明出现在中间不生效——防止多轮澄清后旧声明被复用误抑制。
- 声明生效即放行 hook 并记入 `events-<hostname>.jsonl` 的 `declared` 事件。

CI 侧的豁免走另一通道（PR 模板理由 / `docs-exempt` 标签），见 §6。

## 6. 豁免协议（PR 通道，记录制）

豁免成立需**三条同时满足**：

1. PR 打有 `docs-exempt` 标签；
2. 标签时间**晚于最近一次 synchronize（推送）事件**——旧标签不豁免新推送，防"僵尸豁免"（重新打一次标签即可确认）；
3. PR 描述存在 `理由：<非空>` 声明行（按行匹配 `理由：`，不做整句子串匹配）。

豁免成立时 CI 在 job summary 记录：规则清单 / 理由 / head SHA（**豁免与 SHA 绑定，换 SHA 即重审**）。
**无理由或标签过期 → CI 失败**（不允许空白/僵尸豁免）。

## 7. 本层保证与不保证（必须明示）

- **保证**：must 命中时"至少动过一个 `required_doc`，或存在一条被记录的豁免/声明"。
- **不保证**：动的对不对、够不够——正确性由 PR 评审与审计层承担。

hook 输出固定附一句："本提示仅本地层；PR 合入前 CI 仍会检查——豁免需在 PR 走记录通道"，
避免用户误以为 hook 放行等于全程放行。

## 8. 已知盲区（不臆断）

1. Bash/sed/heredoc 写文件、MCP 文件工具、手动编辑器改动——**不进 hook 的 edits 记录**，由 CI 层基于 git 事实兜底。
2. hook 级归属只看本会话记录；同工作区多 Claude 并发时，CI 层以 git 事实为准。
3. `git` 子进程在 hgfs 上可能因 `dubious ownership` 假失败——脚本一律降级为"未能判定 + 日志"，**不得把 git 报错当结论**。
4. **编辑记录的轮次边界**（P0b 实测修正）：
   `edits.jsonl` 按会话追加，但 Stop 判定**只消费"上次 Stop 之后新增"的记录**（游标存于
   `last-report.json` 的 `cursor`），故判定是**按轮**的，不是按会话累积。
   - 历史上曾按会话读全量，导致：本会话碰过任意 `.md` 后，后续每次 Stop 都走
     "有文档编辑→整体放行"，**提醒永久失效**。已修，并加回归测试。
   - "文档编辑"的判定也已收窄：仅认 **规则登记的文档** 或 **`md/`（`doc_root`）下的 `.md`**。
     工作区级文件（如 `.claude/doc-sync/*.md`）与仓库根 `README.md` **不算**文档同步，
     不会触发放行。

## 9. 失败模式与回滚

| 失败模式 | 表现 | 处置/回滚 |
|---|---|---|
| hook 脚本报错/超时 | 会话不受影响（exit 0 fail-open） | 看 `events-<hostname>.jsonl` 错误行；修脚本 |
| hook 误扰频繁 | 每次 Stop 都被打扰 | ① `hook.mode→remind` ② `DOC_SYNC_DISABLE=1` 临时 ③ 删配置（改配置后需新会话生效） |
| CI 误红 | PR 因初筛失败但确无需文档 | PR 豁免（必须给理由）；规则过宽 → 收窄 glob 或降 tier；紧急：`gates.mode→observe` |
| doc-map 腐烂 | glob 不命中（文件改名/移动） | `--validate` 直接 FAIL 并指出规则 id；改 map 即恢复 |
| 双 Claude 并发（同机） | 归属混淆 | hook：归属=本会话记录（`edits.jsonl` 按 `session_id` 过滤），天然隔离 |

> **VM 只读约定（2026-10-11 起）**：VM（`/mnt/hgfs/heima`）**不再写入任何代码**，
> 仅作为运行/验证环境读取共享目录。故原"host/VM 同写撞 `git index.lock`"的风险**已消除**，
> 不再需要"同一时间只一台机器写工作区"的运维约定。
> 但 VM 仍会**执行**本机制的 hook 脚本（P0a 已实测通过），故路径解析与编码处理在 VM 侧仍须保持正确。
| host/VM 路径差异 | 脚本路径失效 | 脚本只用"repo root 探测 + 相对路径"；settings 用 `$CLAUDE_PROJECT_DIR` |
| hgfs git 子进程失败 | check/validate 假红 | 降级 + 日志 + 明示"未能判定"；配 `git safe.directory` |
| hook 接口随 CC 版本变化 | 字段缺失 | 接口留档于运维手册；脚本容错 fail-open；升级后对照官方 hooks 参考复核 |
| CRLF / shebang 崩坏 | hook 脚本无法执行 | `.gitattributes` 强制 `*.sh`/`*.py` LF（已提交，见实施计划） |
| `settings.local.json` 被 VM 误提交 | 噪音 diff | `.gitignore` 补 `.claude/settings.local.json`（已提交） |
| 双份脚本漂移（两仓库各一份） | 行为不一致 | 脚本内置 `DOC_SYNC_HOOK_VERSION`；审计比对两份版本 |

## 10. 指标定义（月度计算）

| 指标 | 算法 | 健康区间（初定） |
|---|---|---|
| 豁免率 | 豁免事件数 ÷ must 违规拦截数 | 稳定后 <30% |
| 误报率（估算） | 审计对当期豁免抽样 5 个、人工判定"确实无需更新"的比例；**须附样本量** | <20% |
| 漏报数（估算） | 审计抽样发现的失真项数；**附样本量**（漏报无天然分母，一律呈现为"样本量+估计值"） | 趋势下降 |
| 映射覆盖率 | `--validate` 输出 | ≥ 阈值（初定 70%） |
| 触达率 | must 规则 `code[]` 变更合入后 7 天内 `docs[]` 被触达的比例 | 趋势上升 |

> 原"时差中位数"因无法可靠配对而弃用，改用"触达率"作更新延迟的代理指标。
