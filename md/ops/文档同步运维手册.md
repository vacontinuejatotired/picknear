# 文档同步运维手册

本文是「代码改动 → 文档同步」机制的**运维手册**：hook 接口事实、日常操作、检查命令、开关与排障。
规范与判定规则见 [文档同步规范](../规范/文档同步规范.md)；阶段与验收见 [文档同步实施计划](../规范/文档同步实施计划.md)。

> **P0a 探针结论已并入本文 §3**（2026-10-11 真机实测，14 项）。
> 凡本文与旧计划文档冲突处，**以本文实测为准**。

## 1. 机制总览

三层，逐层加严：

| 层 | 载体 | 时机 | 行为 | 阶段 |
|---|---|---|---|---|
| ① 实时提醒 | Stop hook | 每回合结束 | `remind`：只提醒用户不唤醒模型；`block-must`：must 命中续跑一次 | P0b 起 |
| ② CI 守门 | `ci` job 的 `docs-sync gate` step | PR / push | `observe` 只报告；`enforce` 拦截 | P1 |
| ③ 定期审计 | 本地 scheduled task | 每周 | 语义抽样，只报告不阻断 | P2 |

## 3. hook 接口事实（P0a 实测，2026-10-11）

### 3.1 Stop stdin 字段（实测齐全）

`session_id` / `transcript_path` / `cwd` / `prompt_id` / `permission_mode` / `effort{level}` /
`hook_event_name` / **`stop_hook_active`** / **`last_assistant_message`**（上一轮回复全文）/
`background_tasks[]` / `session_crons[]`。

- ✅ `last_assistant_message` **完整携带**上一轮回复全文 ⇒ **声明检测直接用它，不解析 transcript**。
- ⚠️ `permission_mode` 是**会话态快照**（实测出现 `auto`、`acceptEdits`），脚本不得对其取值做硬编码假设。

### 3.2 PostToolUse stdin 字段（实测）

`session_id` / `transcript_path` / `cwd` / `prompt_id` / `permission_mode` / `effort{level}` /
`hook_event_name` / `tool_name` / `tool_input{file_path, content}` /
`tool_response{type, filePath, content, structuredPatch, originalFile, userModified}` / `tool_use_id` / `duration_ms`。

- ⚠️ **`tool_input.file_path` 是 Windows 反斜杠绝对路径**（`E:\heima\...`）⇒ 判定前**必须** `\`→`/` 归一化。
  库函数 `doc_sync_lib.normalize_path()` 已统一处理。
- `stop_hook_active` 在 PostToolUse 上**不存在**（`null`）——仅 Stop 事件有此字段。

### 3.3 三种输出的真机行为（**关键，与初版计划有出入**）

| 输出 | 事件 | 实测注入标签 | 行为 |
|---|---|---|---|
| `systemMessage` | Stop | `Stop says:`（harness 自动前缀） | 用户可见，**不续跑**，不阻断 |
| `hookSpecificOutput.additionalContext` | Stop | `Stop hook additional context:` | **续跑一次**，非错误样式 |
| `hookSpecificOutput.additionalContext` | PostToolUse | `PostToolUse:Edit/Write hook additional context:` | 注入上下文，不阻断工具 |
| `decision:"block"` + `reason` | Stop | `Stop hook blocking error…` | **续跑一次**，**错误样式** |
| `decision:"block"` | PostToolUse | `PostToolUse:Write hook blocking error from command: "…"` | **错误样式**，但**不阻止**已完成的工具 |

**三条必须遵守的结论**：

1. **续跑的注入标签是 `Stop hook additional context`**，不是早期计划写的 "Stop hook feedback"。
   功能语义一致（非错误反馈、对话继续），但**照旧文档 grep "Stop hook feedback" 会落空**。
2. **`additionalContext` 的续跑不会产生第二次 Stop**（`stop_hook_active` 在该路径恒 `false`）；
   **只有 `decision:"block"` 的续跑会二次 Stop 并带 `stop_hook_active=true`**。
   ⇒ **阶段 B 防循环不能依赖 `stop_hook_active`**，必须靠脚本的**内容键去重** + harness 的"连续续跑 8 次上限"兜底。
3. **PostToolUse 上绝不可输出任何内容**（含 `decision:"block"`）：
   `blocking error` 会被误读为命令失败（实际工具成功），
   `additionalContext` 会让提醒从"回合级"退化成"**每次编辑都刷屏**"。
   ⇒ `doc_sync_record.py` 恒定静默（只落盘、exit 0）；一切输出只由 `doc_sync_stop.py` 产出。

### 3.4 运行环境要求（Python 版本 —— 强制）

**要求：Python ≥ 3.8**，仅使用标准库（**无第三方依赖，无需 pip install**）。

- 脚本已由 AST 核对确认：无 `match/case`（3.10+ 专属）、无运行时 `X | Y` 联合类型
  （全部联合类型位于函数注解、由 `from __future__ import annotations` 延迟求值），
  亦无 3.9+/3.10+ 专属 stdlib。故理论下限低至 3.7；这里取 **3.8** 作为工程下限（3.7 已 EOL）。
- **wrapper 自带版本守卫**：`doc_sync_hook.sh` 会依次探测 `python3 → python → py -3`，
  只接受 `>= 3.8` 的解释器；全部不可用或版本过低时 **静默 exit 0**（fail-open），
  并尽力追加一条 `events-wrapper.jsonl` 错误日志。
- **新环境接入步骤**：确认任一 `python3` / `python` / `py` ≥ 3.8 在 `PATH` 上即可，无需其它配置。
  可用下面一行自检：

  ```bash
  python3 -c "import sys; print(sys.version_info); assert sys.version_info >= (3, 8)"
  ```

- 编码：wrapper 强制 `PYTHONUTF8=1` 与 `PYTHONIOENCODING=utf-8`，
  避免 Windows 默认 GBK 破坏中文路径与输出文案（hgfs 跨 host/VM 场景必需）。

#### 实测解释器对照（2026-10-11）

| 环境 | `python3` | `python` | `py` | 实际命中 |
|---|---|---|---|---|
| 宿主（Win11 / Git Bash） | `/c/msys64/ucrt64/bin/python3` (3.12.12) | CPython 3.11.7 | `/c/WINDOWS/py` (3.11.7) | `python3`（**MSYS2**） |
| VM（Ubuntu / hgfs） | `/usr/bin/python3` (3.10.12) | 不存在 | 不存在 | `python3` |

> 宿主 `python3` 落在 MSYS2。当前实现只用标准库故无影响；
> 若将来引入依赖或大量使用 `pathlib` 与 Windows 盘符混算，需在宿主实测确认。

- `.sh`/`.py` **必须 LF**（`.gitattributes` 已强制）；调用处一律 `sh 显式启动`（hgfs 不保证执行位）。
- 宿主 `E:\heima` 与 VM `/mnt/hgfs/heima` 经 hgfs **指向同一份 `.claude/doc-sync/`**，日志天然汇合。

### 3.5 配置加载

- hooks 配置**会话内修改即被即时加载**（实测），无需重启会话；但重大变更后保险起见新开一次会话再验。
- 宿主已有**用户级 Stop hook**（`C:\Users\Ntwitm\.claude\settings.json` 的通知器）：并行运行、互不覆盖，无需避让。
- 新目录首次运行会有一次**信任确认**（VM 上首次生效前需确认）。

## 4. 日常检查命令

```bash
# 仓库根：picknear/
cd E:/heima/picknear

# 1. doc-map 健康检查（CI 每次必跑；FAIL 恒 exit 1，WARN/INFO 不阻断）
python scripts/docs/doc_sync_check.py --validate

# 2. 内容时效 + 覆盖率报告（恒 exit 0）
python scripts/docs/doc_sync_check.py --report

# 3. 本地模拟一次 PR 判定（observe 只报告；enforce 才 exit 1）
python scripts/docs/doc_sync_check.py --gate --base master --head HEAD --mode observe
python scripts/docs/doc_sync_check.py --gate --base master --head HEAD --mode enforce

# 4. 本地自测（62 项，无会话即可跑）
python scripts/docs/doc_sync_selftest.py

# 5. 既有文档规范回归
python scripts/docs/check_docs.py
```

CI 上下文经环境变量传入（`--gate`）：
`DOC_SYNC_BASE` / `DOC_SYNC_HEAD` / `DOC_SYNC_PR_BODY` / `DOC_SYNC_LABELS` /
`DOC_SYNC_LABELED_AT` / `DOC_SYNC_LAST_SYNC_AT` / `DOC_SYNC_MODE`。

## 5. 开关与回滚

| 开关 | 位置 | 效果 |
|---|---|---|
| `DOC_SYNC_DISABLE=1` | 环境变量 | 脚本级紧急静默（hook 全放行） |
| `hook.mode` | `doc-map.json` | `remind`（默认，只提醒）↔ `block-must`（must 续跑） |
| `gates.mode` | `doc-map.json` | `observe`（默认，只报告）↔ `enforce`（CI 拦截） |

**回滚**：

- 只关"续跑"：`hook.mode → remind`。
- 临时全静默：设 `DOC_SYNC_DISABLE=1`。
- 彻底移除：删各处 hook 配置（`E:\heima\.claude\settings.local.json` + `picknear/.claude/settings.json`），
  **改配置后需新会话生效**。

## 6. 日志与排障

运行态全部在 `E:\heima\.claude\doc-sync\`（已 gitignore）：

| 文件 | 内容 |
|---|---|
| `edits.jsonl` | PostToolUse 记录（每行：ts / session_id / tool_name / file_path / normalized） |
| `events-<hostname>.jsonl` | 判定事件：`report` / `declared` / `skip_docs_edited` / `error` |
| `last-report.json` | 内容键去重状态（防同状态反复打扰） |

**排障顺序**：

1. 看 `events-<hostname>.jsonl` 的 `error` 行（脚本内部错误全部 fail-open，只在此留痕）。
2. `static`：`python scripts/docs/doc_sync_selftest.py` —— 62 项全绿说明脚本逻辑没问题。
3. 判定不符预期：`--validate` 看 glob 是否命中；`events` 看是否 `skip_docs_edited`（改了 .md 即放行）。
4. 完全无反应：确认 hooks 已加载（改配置需新会话）、`CLAUDE_PROJECT_DIR` 正确、解释器可用。

**常见现象对照**：

| 现象 | 原因 |
|---|---|
| `edits.jsonl` 有记录但 Stop 无提醒 | 本回合改了 `.md`（放行）／已声明／命中内容键去重／只改 unmanaged |
| 提醒一次后不再提醒 | 内容键去重生效（**预期行为**，同一状态不重复打扰） |
| 中文路径文档被判"未跟踪" | `git ls-files` 未加 `-z` 导致 C-quoting——库已用 `-z` 修正 |
| `error: read_edits … corrupt line(s)` | `edits.jsonl` 有损坏行（已跳过，不影响判定） |

## 7. 已知局限（**重要：机制的静默性**）

本机制**全链路 fail-open**：hook 报错、git 调用失败、载荷格式变化，一律**不阻断会话**。
这样设计是对的（文档机制不该卡住开发），但**代价是机制坏了可能长期无人察觉**。

缓解手段（按可靠度排序）：

1. **主动自检**：怀疑"最近怎么不提醒了"时，先跑
   `python scripts/docs/doc_sync_selftest.py`（62 项）。全绿 ⇒ 脚本没问题，去查配置/加载。
2. **错误留痕**：所有内部错误写入 `events-<hostname>.jsonl` 的 `error` 行（`where` 标明出处：
   `stop` / `record_stdin` / `stop_stdin` / `read_edits` / `load_map` / `hook_wrapper`）。
3. **P2 审计**（尚未上线）会在每周扫描 `events-*.jsonl` 与 `--validate`，是**唯一**的主动发现通道。
   在 P2 上线前，"机制是否还活着"只能靠上述 1、2 两条人工兜底。

### 7.1 覆盖率缺口（当前 60.6%）

`--validate` 报 WARN 的 60.6% 意味着：`com/hmdp/service`、`voucher`、`shop`、`content`、
`controller`（顶层）等目录**未被任何规则覆盖**——改这些目录的代码，hook 与 CI **都不会有任何反应**。

这是**有意的起步范围**（规范 §3.1 定义的 must 类型先落地），不是遗漏。
P0c 观察期应依据实际误报/漏报数据决定往哪补规则；补齐后覆盖率应达 70% 阈值以上。

### 7.2 归属只看会话记录

hook 层的"谁改的"只认本会话 `edits.jsonl`。故下列改动**不进 hook 记录**，
只能靠 CI 层的 git 事实兜底：Bash 重定向/脚本写文件、MCP 文件工具、手动编辑器改动。

## 8. 审计与指标
- 载体：本地 scheduled task，每周一 09:07；产出 `E:\heima\vm-docs\doc-sync-audit\YYYY-WW.md`。
- 内容三要素缺一不可：① 失真项清单（含证据 diff 引用）② 指标表（凡"估算"附样本量）③ 孤儿文档/陈旧规则提示。
- 指标算法与健康区间见 [文档同步规范 §10](../规范/文档同步规范.md)。
- **审计永不阻断任何流程**；连续无人处理 >2 期 → 下期报告顶部标红。
