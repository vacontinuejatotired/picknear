# PickNear 服务器镜像部署指南（Pull 模式）

> **适用场景**：新服务器 / VPS / 演示机——**不构建镜像**，从阿里云 ACR 拉取现成镜像 + docker compose 部署。
> **前置**：镜像由 CI/CD（`ci-cd.yml`）自动构建推送 ACR——push `master` → CI 通过后自动构建，或手动触发 `workflow_dispatch`（见 `Docker部署指南.md` §1）。构建规范见 `CI流水线.md` §4。
> 本 VM 的开发/构建/部署见 `vm-docs/VM部署交接文档.md`。

## 1. 服务器准备

| 项 | 要求 |
|---|---|
| Docker | Engine ≥20.10 + compose 插件（`docker compose version` 可用） |
| 内存 | ≥5G（容器上限合计 ~2.9G）；swap ≥2G |
| 磁盘 | ≥30G（实际用量 ~10G） |

**镜像加速器**（可选，但拉 mysql/redis/rabbitmq 官方镜像强烈建议）：

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'JSON'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1panel.live"
  ]
}
JSON
sudo systemctl restart docker
```

## 2. 登录阿里云 ACR

```bash
docker login --username=<你的ACR用户名> <你的ACR地址>
```

> 密码 = **阿里云容器镜像服务 → 访问凭证页设置的 registry 密码**（不是账号登录密码）。非交互环境用 `--password-stdin` 从 stdin 读。

## 3. 准备部署目录与配置文件

**不再需要跨仓库相对路径**（2026-10-05：nginx.conf 已并入前端镜像，compose 不再挂载它，
所以也不必维持 `../../nginx-1.18.0heima/frontend/` 那两层目录）：

```
<部署根>/                        # 例：/opt/picknear
└── picknear/
    ├── docker-compose.yml       # ① 编排文件
    ├── .env                     # ② 密钥 + 全部配置（统一走环境变量，§4）
    └── src/main/resources/db/
        └── heima-init.sql       # ③ MySQL 首次初始化脚本（仅数据卷为空时执行）
```

从构建机/工作区（`E:\heima` 或 `/mnt/hgfs/heima`）拷贝这 3 项：

```bash
mkdir -p <部署根>/picknear/src/main/resources/db

scp picknear/picknear/docker-compose.yml                   root@<服务器>:/opt/picknear/picknear/
scp picknear/picknear/.env                                 root@<服务器>:/opt/picknear/picknear/
scp picknear/picknear/src/main/resources/db/heima-init.sql root@<服务器>:/opt/picknear/picknear/src/main/resources/db/
```

> ⚠️ 服务器上**不需要** Dockerfile / src / 前端源码（构建源），`--no-build` 直接用镜像。
> 前端 `nginx.conf` 由前端仓库 CI 构建进镜像，改配置走 push → CI → watchtower，不要在服务器上手工改。

## 4. 配置 .env

compose 从 **compose 文件同目录**的 `.env` 读取变量。全部必填（任一缺失 compose 直接报错或 app 启动报 `Could not resolve placeholder`）：

```bash
cd /opt/picknear/picknear && cp .env.example .env
```

```ini
# ---- 必填：MySQL ----
DB_PASSWORD=你的MySQL root密码        # 必须与现有库一致

# ---- 必填：Redis ----
REDIS_PASSWORD=你的Redis密码          # compose 用它启动 redis，app 用它连接，两处必须一致

# ---- 必填：RabbitMQ ----
RABBITMQ_USERNAME=qyh
RABBITMQ_PASSWORD=你的RabbitMQ密码    # ⚠️ 仅在 rabbitmq-data 卷首次创建时写入，改了要删卷才生效

# ---- 必填：阿里云 OSS（图片上传）----
OSS_ACCESS_KEY_ID=你的AccessKeyId
OSS_ACCESS_KEY_SECRET=你的AccessKeySecret

# ---- 必填：通义千问 AI ----
DASHSCOPE_API_KEY=sk-ws-你的Key

# ---- 必填：Langfuse 云观测（app 启动必需，缺失会崩）----
LANGFUSE_BASE_URL=https://cloud.langfuse.com
LANGFUSE_PUBLIC_KEY=你的pk-lf-...
LANGFUSE_SECRET_KEY=你的sk-lf-...
LANGFUSE_BASIC_AUTH=你的base64(pk:sk)

# 可选：日志级别（缺省 INFO）
# LOG_LEVEL_HMDP=INFO
# LOG_LEVEL_AGENT=INFO
```

> **密码一律不再写进配置文件**（2026-10-05）：`application-prod.yaml` / `application-dev.yaml` 里的
> Redis、RabbitMQ、MySQL 密码都已改成 `${REDIS_PASSWORD}` 这类占位符，缺失即启动失败，逼你从 `.env` 注入。
> `OSS_ENDPOINT`/`bucket`/`region` 仍硬编码在 `application-prod.yaml`，无需配置。`.env` 含密钥，**不要提交进 git**。

### RabbitMQ 改密码的正确姿势

`RABBITMQ_DEFAULT_USER/PASS` 只在 `rabbitmq-data` 卷**首次创建**时写入，之后改 `.env` 不生效：

```bash
# 方案 A：进容器改（保留队列数据）
docker compose exec rabbitmq rabbitmqctl change_password <user> <新密码>
# 同步改 .env 的 RABBITMQ_PASSWORD，再 docker compose up -d app

# 方案 B：删卷重建（队列数据全丢，仅全新环境可用）
docker compose down && docker volume rm picknear-rabbitmq-data && docker compose up -d
```

## 5. 拉取并启动

```bash
cd /opt/picknear/picknear

# 语法校验（可选）
docker compose config

# 拉取全部镜像（app/frontend 走 ACR，依赖走 Docker Hub/加速器）
docker compose pull

# 启动：--no-build 强制用已拉镜像，避免触发构建
docker compose up -d --no-build
```

> 首次启动会创建 MySQL 数据卷并执行 `heima-init.sql` 初始化。启动顺序有依赖：MySQL→Redis→RabbitMQ 逐个 `healthy` → app → frontend。
>
> **app 启动时会跑 Flyway**：首次接管已有库会自动建 `flyway_schema_history` 表并把当前 schema 记为版本 1（baseline），
> 之后 `db/migration/V2__*.sql` 这类增量脚本会按版本自动执行。详见 `picknear/md/ops/Docker部署指南.md` 的「数据库迁移」章节。

## 7. 更新流程（代码改动后）

构建机 push 新镜像（CI/CD 自动或手动触发）→ 服务器拉取替换（同 tag 自动替换）：

```bash
# 构建机：改代码 push 到 master（或手动触发 ci-cd.yml workflow_dispatch）
# 镜像自动构建推送 ACR（见 Docker部署指南.md §1 / CI流水线.md §4）

# 服务器
cd /opt/picknear/picknear
docker compose pull
docker compose up -d --no-build
```

> push 到 `master` 自动触发构建；后端在 `feature` 开发、合并到 `master` 才构建。紧急改动也可手动触发 `workflow_dispatch`（指定 tag），但服务器默认用 `latest` 会同步拿到。

## 8. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `docker compose up` 报 `required variable DB_PASSWORD is missing` | `.env` 缺失或变量为空 | 确认 `/opt/picknear/picknear/.env` 存在且有值（§4） |
| `unauthorized: authentication required` | 未登录私有仓库 | 重新 `docker login`（§2） |
| 拉官方镜像超时 | 加速器未生效 | 检查 daemon.json → `systemctl restart docker` |
| app 崩溃 `Could not resolve placeholder 'REDIS_PASSWORD'` | `.env` 缺 Redis/RabbitMQ 密码 | 补上真值（§4）。2026-10-05 起密码不再写在配置里，缺了就是这个错 |
| Flyway 启动失败 `Found non-empty schema without metadata table` | 生产库已建表但无 `flyway_schema_history` 表 | `application-prod.yaml` 已开 `baseline-on-migrate: true`，正常不会出现；出现说明 baseline 配置被改掉了 |
| Flyway 校验失败 `Validate failed: Migration checksum mismatch` | 有人改了已执行过的迁移脚本 | 脚本一旦执行就禁止再改，新增一个更高版本的脚本来修正 |
| app 一直不 healthy | 依赖未就绪 / DB 密码不一致 | `docker compose logs app`，先等依赖 healthy |
| 前端 502 | 后端未起 / nginx 配置问题 | `docker compose ps` 看 app 是否 healthy；nginx.conf 已随镜像分发，需改则走前端仓库 push → CI |
| 改了 nginx.conf 不生效 | 配置现在在镜像里，不在宿主机 | 确认改的是**前端仓库**的 `nginx.conf` 并已 push 触发 CI 重建镜像（§3） |
| 端口冲突 | 宿主机已有 8080 等占用 | compose 已用非常用端口（48080/48082/43307/46379/45672/55672） |
