# PickNear 日志查看与配置指南

> 每次调日志都踩坑，这里集中记录。改日志前先读这篇，特别是"常见坑"。

---

## 0. 快速结论（TL;DR）

- **中间日志看不到 = 日志级别被过滤，不是没打印**
- 想开 AI 调试日志：`LOG_LEVEL_AGENT=DEBUG LOG_LEVEL_AGENT_TOOL=DEBUG docker compose up -d`
- **⚠️ 改了环境变量必须 `docker compose up -d`（recreate 容器）**，`restart` 不生效
- 看单容器日志：`dclf app`（在 root 终端，`source ~/.bashrc` 确保 alias 是新的）

## 1. 怎么看日志

| 想干什么 | 命令 |
|---|---|
| 跟随后端日志 | `dclf app`（=`docker compose logs -f app`，无 tail） |
| 限制行数 | `dclf --tail=100 app` |
| 只看最近 30 分钟 | `docker compose logs --since 30m app` |
| 所有容器 | `docker compose logs -f`（或 `dclf`） |
| 绕开 compose | `docker logs -f picknear-app`（容器名） |
| 进入容器 | `dcex app sh` |

## 2. 日志级别体系（两层，优先级从低到高）

| 层 | 位置 | 作用 |
|---|---|---|
| 1. jar 内配置 | `application.yaml`（注释里预留了细分开关） | 打包时写死，一般不动 |
| 2. 环境变量 | docker-compose `environment`（优先级最高） | **启动时控制，推荐用这层** |

> 统一走 env：日志级别不再用挂载的 `config/application-prod.yaml` 覆盖（2026-08-05 移除）。

## 3. 启动时日志开关（推荐用法）

docker-compose `app` 服务已配置 6 个环境变量，默认全 `INFO`：

| 环境变量 | 控制范围 |
|---|---|
| `LOG_LEVEL_HMDP` | 全部 hmdp 包 |
| `LOG_LEVEL_AGENT` | AI 主链路（`com.hmdp.agent`） |
| `LOG_LEVEL_AGENT_GUARD` | **工具调用守卫判定**（`com.hmdp.agent.guard`，放行/拦截是 debug） |
| `LOG_LEVEL_AGENT_TOOL` | 工具 Bean 收集（`com.hmdp.agent.tool`，一般没有 debug 日志） |
| `LOG_LEVEL_PROMPTHOOK` | Hook 链执行（`com.hmdp.agent.hook`，Hook 判定结果是 debug） |
| `LOG_LEVEL_INTERCEPTOR` | 拦截器链（`com.hmdp.interceptor`） |

> ⚠️ 包名对应以代码为准：`com.hmdp.agent` 下**只有 guard 和 hook 两个包有 debug 日志**（2026-08-02 用 grep 全量确认）。没有 `com.hmdp.promptguard` 包（Prompt 注入检测在 agent.hook 里），compose 里已无该开关。

**一次性开启**（下次启动恢复默认）：

```bash
# 在 /opt/picknear/picknear 下
LOG_LEVEL_AGENT=DEBUG LOG_LEVEL_AGENT_TOOL=DEBUG docker compose up -d
```

**持久开启**（写入 `.env`）：

```bash
echo 'LOG_LEVEL_AGENT=DEBUG' >> /opt/picknear/picknear/.env
docker compose up -d
```

**关闭/恢复默认**：
- 一次性：下次启动不带变量即可
- 持久：从 `.env` 删除对应行，再 `docker compose up -d`

## 4. 常见坑（血的教训）

### 坑 1：中间日志看不到（最常见）
现象：只有"HOOK 正在准备执行"和"Phase1 回复完成"，中间的 Hook 判定结果、LLM 调用、工具调用全没。
原因：那些是 **DEBUG 级别**（`PromptHookChain.java:63` Hook 判定结果、`GuardedToolCallback.java:93` / `ToolGuardManager.java:69` 工具调用放行都是 `log.debug`），生产只开了 `com.hmdp: INFO`。
解决：开 `LOG_LEVEL_AGENT_GUARD` + `LOG_LEVEL_PROMPTHOOK`（工具调用 + Hook 判定），见 §3。

### 坑 2：改了环境变量但 restart 没生效
环境变量变化**必须 recreate 容器**：`docker compose up -d`（up 会检测配置差异自动重建）。
`docker compose restart` 只重启进程，**不重新读环境变量**。

### 坑 3：`dclf app` 显示全部容器的日志
原因（2026-08-02 实际踩到）：root 的 `~/.bashrc` 里 `dclf` 别名定义被写坏了——**引号内有换行**：
```
alias dclf="docker compose logs -f ⏎
  --tail=100"
```
展开后 `app` 参数被换行切断，变成执行 `docker compose logs -f`（全部）。
修复：合并成单行后 `source ~/.bashrc`。自查：`type dclf` 必须是**一行**输出。

### 坑 4：`! 前缀` 或 Claude 会话里 `type dclf` 查不到
`!` 前缀跑在 Claude 的会话（docker 用户、**非交互 shell**）里，非交互 shell **不加载 alias**，查不到是正常的。
要看/用 alias 必须去 root 交互终端。验证用：`sudo -u root bash -ic 'type dclf'`。

### 坑 5：改了环境变量 vs 改了 compose
| 改动位置 | 生效方式 |
|---|---|
| `.env` 里的 `LOG_LEVEL_*`（经 compose environment 透传） | **必须 `docker compose up -d`** |
| 代码/镜像 | 重新构建 + `docker compose up -d` |

## 5. 排查套路（日志看不到时按顺序）

1. 确认容器环境变量：`docker inspect picknear-app --format '{{range .Config.Env}}{{println .}}{{end}}' | grep LOGGING_LEVEL`
2. 看代码里是 `log.info` 还是 `log.debug` —— debug 就是要开级别
3. 按 §3 开对应包 DEBUG，**up -d** 生效
4. 看完整链路：`dclf app`
